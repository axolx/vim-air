1. INTRODUCTION                                          *air-introduction*

vim-air treats an LLM as a reviser. You give it a prompt and a region of text;
it produces a proposed new version in a scratch buffer beside the original,
in Vim's native diff mode. You then accept or reject changes with |]c|, |[c|,
|do| and |dp|.

There is no bespoke review UI, no floating windows and no virtual text. The
review interface is the one you already know.

It is built for prose as much as for code. Copy editing, tightening, removing
clichés and checking claims are first-class uses.

==============================================================================
2. REQUIREMENTS                                          *air-requirements*

- Vim 8.0 or later, or Neovim. Pure Vimscript; no Lua or Python host.
- One backend's CLI. The default, AWS Bedrock, is described here; to use an
  OpenAI API key instead, see |air-backend-openai|.
- The AWS CLI v2 on your $PATH, with working credentials.
- Amazon Bedrock model access granted in your account and region.
- A model ID in |g:air_model| — there is no default, because Bedrock model IDs
  are account- and region-specific.

vim-air never handles credentials. The AWS CLI resolves them however you
already do: environment variables, a config profile, SSO, or an instance or
container role. Use |g:air_aws_profile| and |g:air_aws_region| to pick among
them.

Minimum configuration: >

    let g:air_model = 'us.anthropic.claude-sonnet-4-20250514-v1:0'
    let g:air_aws_region = 'us-east-1'   " or rely on your AWS config

Verify the plumbing outside Vim first: >

    aws bedrock-runtime converse --model-id "$MODEL" \
        --messages '[{"role":"user","content":[{"text":"hi"}]}]'

For the OpenAI API, see |air-backend-openai|.

3. QUICK START                                            *air-quickstart*

Revise the whole buffer, typing the prompt in a scratch buffer: >

    :Air
    (type "Tighten the prose. Preserve my voice.", then press <CR>)

Revise with a one-line prompt: >

    :Air tighten the opening paragraph

Revise the visual selection: >

    :'<,'>Air reduce passive voice

Use a named prompt (see |air-named-prompts|): >

    :Air grammar

Then review: >

    ]c      next change
    [c      previous change
    do      take the proposed hunk (from your buffer)
    dp      send the proposed hunk to your buffer (from the proposal)
    :AirClose

A hunk you skip leaves your text unchanged.

==============================================================================
4. COMMANDS                                                  *air-commands*

                                                                      *:Air*
:[range]Air [options] [prompt]
        Revise text and open a diff split with the proposal.

        With no [range], the scope is |g:air_default_scope| ("buffer").
        With a [range], only those lines are revised, but the diff is still
        presented against the whole buffer.

        [prompt] may be:
        - literal prompt text
        - the name of a prompt in |g:air_prompts| (see |air-named-prompts|)
        - "@x" to read register x
        - omitted entirely, which opens the |air-prompt-buffer|

        [options] may be:
            -scope={name}   override the scope, see |air-scopes|

                                        *:AirBuffer* *:AirParagraph* *:AirSection*
:AirBuffer [options] [prompt]
:AirParagraph [options] [prompt]
:AirSection [options] [prompt]
        Shorthands for the corresponding |air-scopes|.

                                                                *:AirAbort*
:AirAbort
        Cancel the request in flight. Only one request runs at a time; |:Air|
        refuses another until this one finishes or is aborted. A blocking
        request (|g:air_async| off, or no job support) cannot be cancelled.

                                                                *:AirClose*
:AirClose
        Close the proposal window, run |:diffoff| on the source window and
        restore the window options, window sizes and 'diffopt' that were
        changed for the session. Works from any window, including one in
        another tab. Closing the proposal with |:quit| or |:bwipeout|
        restores them too. Only one review exists across the editor; a new
        proposal closes the previous review.

                                                                  *:AirLog*
:AirLog
        Show the recent request/response log, including the full stdout and
        stderr of failed backend invocations.

5. SCOPES                                                      *air-scopes*

The scope decides which lines are sent for revision. The proposal always
contains the entire buffer with only that region replaced, so hunk-by-hunk
merging works normally.

buffer      The whole buffer. Default.
range       The given [range], or the visual selection. With neither, the
            cursor line.
paragraph   The contiguous non-blank block around the cursor. From a blank
            line, the next paragraph forward.
section     A Markdown heading through the next heading of the same or a
            higher level. Deeper subsections are included. With no heading
            above the cursor, falls back to the whole buffer. Only "#"
            headings count, and a "#" line inside a fenced code block is
            taken for one; underlined headings are not recognized.
motion      The lines covered by an operator; see |<Plug>AirMotion|.

6. THE PROMPT BUFFER                                    *air-prompt-buffer*

A bare |:Air| opens a scratch buffer for composing the prompt. Vim has no
editable modal popup — |popup_create()| buffers are not modifiable — so a
scratch buffer is what gives you full normal and insert mode, undo, registers,
|gq|, spell checking and abbreviations while writing a prompt.

Default mappings inside it:

    <CR>        submit (normal mode only, so <CR> stays a newline in insert)
    <C-s>       submit (normal or insert mode)
    q, <C-c>    cancel
    <C-p>       recall an older prompt
    <C-n>       recall a newer prompt

Everything in the buffer is sent as the prompt. The scope is fixed when the
buffer opens; cancel and rerun |:Air| to change it.

To reuse a prompt file, read it into a register with Vim: >
    :let @p = join(readfile("prompts/copyedit.md"), "\n")
    :Air @p
<
==============================================================================
7. NAMED PROMPTS                                        *air-named-prompts*

Named prompts are reusable instructions. These ship by default:

    tighten     remove repetition and filler, preserve voice
    grammar     grammar, spelling and punctuation only
    passive     reduce passive voice
    cliches     remove clichés and stock phrases
    claims      find unsupported or overstated claims
    simplify    shorter sentences, concrete words
    structure   improve paragraph order and transitions
    docs        add or improve doc comments
    modernize   modernize code, preserve behaviour
    refactor    simplify code, preserve behaviour and interface

                                                            *g:air_prompts*
Add your own, overriding defaults by name: >

    let g:air_prompts = {
      \ 'mcphee': 'Rewrite in the voice of John McPhee. Keep every fact.',
      \ 'tighten': 'Cut 20% of the words without losing meaning.',
      \ }
<
                                                         *g:air_ft_prompts*
Per-filetype prompts take precedence over both: >

    let g:air_ft_prompts = {
      \ 'markdown': {'links': 'Check every link is described by its text.'},
      \ 'go':       {'docs':  'Add godoc comments to exported symbols.'},
      \ }
<
Prompts may use the {filetype} and {filename} placeholders, which are replaced
with the source buffer's 'filetype' and file name. Named prompts complete on
the |:Air| command line.

==============================================================================
8. REVIEWING A PROPOSAL                                        *air-review*

The proposal buffer is a scratch buffer: 'buftype' is "nofile", it is wiped
when closed, and it is 'nomodifiable' unless |g:air_modifiable| is set. It
inherits the source buffer's 'filetype', 'fileformat' and 'fileencoding' so
syntax highlighting and diffing behave.

Move between changes with |]c| and |[c|. Take a hunk with |do| in your
buffer or |dp| in the proposal; only your source buffer needs to be
modifiable. A hunk you skip leaves your text unchanged. Your source buffer is
a normal buffer throughout, so |u| works as always.

The proposal always opens in a vertical split beside the source window, with
the cursor on the first change. While a proposal is open, "q" in it runs
|:AirClose| (see |g:air_proposal_maps|).

If the source has changed since the request was composed, including while you
were writing the prompt, the response is discarded and you are asked to run
|:Air| again. If the source buffer is not visible in the current tab page
when the response arrives, no proposal opens.

If the response is identical to your text, no split opens and vim-air reports
"no changes proposed".

9. CONFIGURATION                                               *air-config*

|g:air_model| is the only setting you must provide, and only for the default
Bedrock backend. The OpenAI backend has its own settings; see
|air-backend-openai|.

                                                              *g:air_model*
The Bedrock model ID or inference profile ID. Required for Bedrock; there is
no default. Ignored by the OpenAI backend.
On-demand access to many models needs the regional inference-profile prefix
("us.", "eu.", "apac."). >
    let g:air_model = 'us.anthropic.claude-sonnet-4-20250514-v1:0'
<
                                                            *g:air_aws_cmd*
The AWS CLI executable. Default "aws". >
    let g:air_aws_cmd = '/usr/local/bin/aws'
<
                                  *g:air_aws_profile* *g:air_aws_region*
Passed to the CLI as --profile and --region when set. Empty means the CLI
resolves them from your environment and config as usual. >
    let g:air_aws_profile = 'work'
    let g:air_aws_region = 'us-east-1'
<
                                                           *g:air_aws_args*
Extra arguments appended to the aws invocation, for anything vim-air does not
model directly. >
    let g:air_aws_args = ['--cli-read-timeout', '0']
<
                              *g:air_max_tokens* *g:air_temperature* *g:air_top_p*
Bedrock inference configuration. Only maxTokens is sent by default (8192);
temperature and topP are omitted unless you set them.

That default is deliberate: newer models, including Claude Sonnet 4.5 and the
reasoning models, reject temperature with a ValidationException saying it is
deprecated. Set it only if your model accepts it. >
    let g:air_max_tokens = 16384
    let g:air_temperature = 0.2
<
                                                   *g:air_inference_config*
Merged over the above, for any other InferenceConfiguration field. >
    let g:air_inference_config = {'stopSequences': ['<<<END>>>']}
<
                                                              *g:air_async*
Run the backend asynchronously via |job_start()| or jobstart(). Default 1.
Falls back to a blocking |system()| call when jobs are unavailable.

                                                            *g:air_timeout*
Seconds before an in-flight request is killed. Default 120. 0 disables.
Asynchronous requests are stopped by a timer. The OpenAI backend also passes
it to curl as --max-time, which bounds requests when jobs are unavailable
too; the Bedrock backend relies on the AWS CLI's own timeouts there.

                                                    *g:air_max_input_bytes*
Confirm before sending more than this many bytes. Default 100000.

                                                            *g:air_diffopt*
'diffopt' value for the duration of a session, restored on |:AirClose|.
Default "internal,filler,algorithm:patience,inline:word": patience hunks,
with the changed words highlighted inside each changed line. Items this Vim
does not support (inline:word needs Vim 9.1.1243 or later) are dropped.
Empty leaves 'diffopt' alone.

                                                        *g:air_modifiable*
Allow editing the proposal before merging. Default 0.

                                                      *g:air_default_scope*
Scope for |:Air| without a range: "buffer" (the default), "paragraph" or
"section". See |air-scopes|.

                                                      *g:air_prefill_last*
Whether to prefill the prompt buffer with the previous prompt. Default 1.

                            *g:air_history* *g:air_history_file* *g:air_history_size*
Prompt history: enabled (default 1), storage path (default
~/.cache/vim/air-history.jsonl, or air-history.jsonl in stdpath('cache') in
Neovim), and how many prompts to keep (default 200). A prompt is recorded
when its request is sent; a repeated prompt moves to the newest position.

                                                      *g:air_system_prompt*
The instruction that forces plain-text-only output, sent as the Bedrock
system field or as the OpenAI "instructions". Override with care: chat-tuned
models otherwise narrate their changes, which corrupts the diff.

                                                       *g:air_proposal_maps*
Map "q" to |:AirClose| in the proposal buffer. Default 1.

                                                           *g:air_log_size*
Log entries to retain. Default 50.

Removed configuration: g:air_prompt_ui, g:air_split and g:air_openai_params
are ignored. Use the prompt buffer, a vertical split and
|g:air_openai_max_output_tokens|. The removed -model= and -f command options
report an unknown option. Configure the backend model and use a register for
prompt files.

10. MAPPINGS                                                 *air-mappings*

vim-air defines no default mappings. These |<Plug>| mappings are provided:

    <Plug>AirRevise      |:Air| (normal), or |:Air| on the selection (visual)
    <Plug>AirParagraph   |:AirParagraph|
    <Plug>AirSection     |:AirSection|
    <Plug>AirMotion      operator, see below
    <Plug>AirClose       |:AirClose|
    <Plug>AirAbort       |:AirAbort|

For example: >

    nmap <Leader>ar <Plug>AirRevise
    xmap <Leader>ar <Plug>AirRevise
    nmap <Leader>ap <Plug>AirParagraph
    nmap <Leader>as <Plug>AirSection
    nmap <Leader>am <Plug>AirMotion
    nmap <Leader>aq <Plug>AirClose
<
                                                          *<Plug>AirMotion*
An operator: it revises the lines covered by the motion or text object that
follows, then opens the |air-prompt-buffer| for the instruction. >

    <Leader>amip     revise the inner paragraph
    <Leader>amaf     revise a function, with a filetype text object plugin
<

11. BACKENDS                                                 *air-backends*

vim-air ships two backends: "bedrock" (AWS Bedrock via the aws CLI, the
default) and "openai" (the OpenAI Responses API via curl).

                                                          *g:air_backend_name*
Selects the backend. Default "bedrock". >
    let g:air_backend_name = 'openai'

OPENAI API                                                *air-backend-openai*

Sends each revision as one POST to the Responses API, billed to your API key.
There is no agent loop and no tool definitions: the request carries the
system prompt, your text, and nothing else. Requirements:

- curl 8.3 or later on your $PATH.
- An OpenAI API key in $OPENAI_API_KEY (see |g:air_openai_api_key_env|),
  exported before Vim starts, or set from your vimrc: >
    let $OPENAI_API_KEY = trim(system('pass show openai/api-key'))
<
Minimum configuration: >

    let g:air_backend_name = 'openai'

With nothing else set, requests use gpt-6-luna at low reasoning effort.

vim-air never reads the key. curl imports it from the environment
(--variable) and expands it into the Authorization header (--expand-header),
so it never appears in argv, in a temp file, or in |:AirLog|. The request body
goes over curl's stdin, and is sent with "store": false. (In Vim's blocking
fallback, |system()| itself passes stdin through a temporary file, which holds
the request body but never the key.)

Verify the plumbing outside Vim first: >

    curl https://api.openai.com/v1/responses \
        -H "Authorization: Bearer $OPENAI_API_KEY" \
        -H 'Content-Type: application/json' \
        -d '{"model":"gpt-6-luna","input":"Say hi."}'
<
A response cut short by max_output_tokens raises the same "truncated"
warning as Bedrock's max_tokens. |g:air_max_tokens| and the other Bedrock
inference settings do not apply; use |g:air_openai_max_output_tokens|.

                                                          *g:air_openai_model*
The model to use. Default "gpt-6-luna". |g:air_model| is not consulted, since
it usually holds a Bedrock ID. >
    let g:air_openai_model = 'gpt-6.1-sol'
<
                                               *g:air_openai_reasoning_effort*
Sent as reasoning.effort, e.g. "low", "medium" or "high". Default "low":
prose revisions rarely need much reasoning, and lower effort is faster and
cheaper. Set it to '' to omit it and use the model's default. >
    let g:air_openai_reasoning_effort = 'medium'
<
                                              *g:air_openai_max_output_tokens*
Maximum output tokens, including reasoning tokens. Default 8192. >
    let g:air_openai_max_output_tokens = 16000
<
                                                       *g:air_openai_base_url*
The API root; "/responses" is appended. Default "https://api.openai.com/v1".
Point it at a proxy or any Responses-compatible endpoint. >
    let g:air_openai_base_url = 'http://localhost:8080/v1'
<
                                                    *g:air_openai_api_key_env*
The name of the environment variable holding the API key. Default
"OPENAI_API_KEY". >
    let g:air_openai_api_key_env = 'AIR_OPENAI_KEY'
<
                                                              *g:air_curl_cmd*
The curl executable. Default "curl".

                                                             *g:air_curl_args*
Extra arguments added to the curl invocation, before the URL. ~/.curlrc is
not read, so proxies and extra headers go here. >
    let g:air_curl_args = ['--header', 'OpenAI-Project: proj_...']

ADDING A BACKEND                                           *air-backend-add*

Adding a backend means dropping one file on your 'runtimepath' at
autoload/air/backend/{name}.vim implementing three functions. Nothing else in
the plugin needs to change: the dispatcher owns argv execution, async and sync
transports, timeouts, aborting, temp-file cleanup and logging.

                                                    *air-backend-interface*
    air#backend#{name}#check() -> string
        '' when the backend is usable, otherwise a user-facing reason such as
        a missing executable or an unset model. Called before every request,
        so misconfiguration is reported without spawning a process.

    air#backend#{name}#request({payload}, {opts}) -> dict
        Describes the subprocess to run:
            argv          list, required
            stdin         string, optional
            cleanup       list of files to delete afterwards, optional
            cleanup_dirs  list of directories to delete afterwards, optional
        {payload} is {'system': ..., 'user': ...}. {opts} is currently empty
        and reserved for future backend options.

    air#backend#{name}#parse({result}) -> dict
        Maps {'status': exit code, 'stdout': ..., 'stderr': ...} onto
        {'ok': 0|1, 'text': ..., 'error': ..., 'warning': ...}.
        Backends extract provider error text; vim-air displays it on one line
        and keeps the full output in |:AirLog|.

A backend must be a real file: Vim raises E746 if an autoload-named function is
defined in a script whose path does not match.

12. HOOKS                                                       *air-hooks*

                                                            *g:Air_backend*
Bypass the backend layer entirely, including subprocess handling. Receives
({payload}, {opts}, {Cb}) and must call {Cb} with a dictionary
{'ok': 0|1, 'text': ..., 'error': ..., 'raw': ...}. Useful for a non-subprocess
transport, and used by the test suite so tests never call AWS. >

    let g:Air_backend = function('MyBackend')

Note the capital: legacy Vim raises E704 for a lowercase variable holding a
|Funcref|. A function name as a string works with either case: >

    let g:air_backend = 'MyBackend'
<
                                                      *g:Air_output_filter*
Post-process the model's text before it is treated as the revision. >

    let g:Air_output_filter = function('StripBanner')

13. TROUBLESHOOTING                                   *air-troubleshooting*

Run |:AirLog| first. It shows the exact argv, the prompt, and the full stdout
and stderr.

"aws not found in $PATH"
    Install the AWS CLI v2, or point |g:air_aws_cmd| at it.

"curl not found in $PATH"
    Install curl 8.3 or later, or point |g:air_curl_cmd| at it.

"$OPENAI_API_KEY is not set"
    Vim did not inherit the key. Export it in the shell that starts Vim, or
    set it from your vimrc (see |air-backend-openai|).

"curl failed: ... option --variable: is unknown"
    Your curl predates 8.3, which added --variable and --expand-header.

"openai: Incorrect API key provided"
    The key in $OPENAI_API_KEY is wrong or revoked.

"openai: The model `...` does not exist or you do not have access to it"
    Set |g:air_openai_model| to a model your API key can use.

"openai: You exceeded your current quota"
    Add credits or raise the spending limit on your OpenAI account.

"openai timed out" or "curl failed: ... Operation timed out"
    Long documents take a while, since the model writes the whole revision
    back. Raise |g:air_timeout|, revise a smaller scope, or lower
    |g:air_openai_reasoning_effort|.

"no model set"
    On Bedrock, set |g:air_model|; there is deliberately no default. On
    OpenAI, |g:air_openai_model| was set to ''; unset it or name a model.

"a request is already in flight"
    Only one request runs at a time. Wait for it, or cancel it with
    |:AirAbort|.

"source buffer changed; run :Air again"
    You edited the source after the request was composed, so the response
    no longer lines up with your text. Run |:Air| again.

"source buffer is no longer visible"
    The response arrived while the source buffer was not shown in the
    current tab page. Show it and run |:Air| again.

"Unable to locate credentials" / "ExpiredToken"
    Refresh credentials the way you normally do (often "aws sso login"), or
    set |g:air_aws_profile|.

"AccessDeniedException"
    The identity needs bedrock:InvokeModel on that model ARN.

"You don't have access to the model"
    Request model access in the Bedrock console, in the region named by
    |g:air_aws_region|.

"`temperature` is deprecated for this model"
    Unset |g:air_temperature| (and |g:air_top_p|). Newer Bedrock models reject
    those parameters; vim-air omits them unless you set them.

"ValidationException"
    Usually the model ID or region. On-demand access to many models requires
    the regional inference-profile prefix, e.g.
    "us.anthropic.claude-sonnet-4-20250514-v1:0" rather than
    "anthropic.claude-sonnet-4-20250514-v1:0".

"response hit maxTokens and is truncated"
    The proposal is incomplete; do not merge it blindly. Raise
    |g:air_max_tokens| or revise a smaller scope.

The proposal starts with an odd or invisible character
    It should not: vim-air strips byte-order marks and leading zero-width and
    non-breaking blanks from every response. If you still see one, run
    |:AirLog| and report the raw response.

The proposal contains commentary, not just the revised text
    The model ignored the system prompt. Try a stronger model, or filter the
    output with |g:Air_output_filter|.

The diff is one enormous hunk
    Your text is probably one long line per paragraph. Vim diffs by line, so
    |do| and |dp| move whole lines; the default |g:air_diffopt| highlights the
    changed words within them. Try one sentence per line for prose, or add
    "iwhite" to |g:air_diffopt|.
